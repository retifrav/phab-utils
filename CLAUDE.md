# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`phab-utils` (on PyPI; it was called `uio-exoplanet-group` until 2025-01-29) is a Python library for querying astronomy databases and processing the results as Pandas tables. It covers the NASA Exoplanet Archive, PADC, Gaia and SIMBAD over TAP/ADQL, and Kepler/K2/TESS light curves through lightkurve. `wiki/` is a separate Markdown knowledge base (HPC, HELIOS, RH1.5D, Jupyter tunnelling and so on) that has nothing to do with the package code.

## Commands

**Before changing lint, type-check or build commands, read `.claude/notes/tooling.md`**: it holds the measurements behind the rules below.

The runtime dependencies (`install_requires` in `setup.cfg`) are not in the container's system Python. Create a uv venv for them, e.g. `uv venv /tmp/phab-venv && VIRTUAL_ENV=/tmp/phab-venv uv pip install -e . pytest pdoc`, and run the tools with that venv's `python -m …`. ruff and ty come with the image, so they need no install.

- **Tests** must run from the repo root, because they open `./data/...` by relative path. The test files are not named `test_*.py`, so `pytest src/phab/tests/` collects **nothing**. Pass the files explicitly:
  ```sh
  python -m pytest ./src/phab/tests/*[^_*].py          # all files (the glob skips __init__.py)
  python -m pytest ./src/phab/tests/databases.py       # one file
  python -m pytest ./src/phab/tests/databases.py -k "test_get_parameters_that_are_double_in_nasa"
  ```
  `strings.py`, `math.py`, `datasets.py` and `files.py` work offline, and so do the `databases.py` tests selected by `-k "mirrors or firewall or range_condition"`. The rest of `databases.py` queries live services (NASA, PADC, SIMBAD, Gaia, MAST), so its results depend on remote data that can change. Before you debug the code, check whether the failure comes from the remote side with a bare `curl` to the endpoint. Two remote problems were seen from this sandbox on 2026-11-22, and the code now works around both:
  - Cloudflare in front of the NASA archive returns a 403 HTML page for some query shapes (see the NASA rule below). In pytest that shows up as `DALServiceError: 403` after `E19: File does not appear to be a VOTABLE`, and the captured log has `getFirewallBlockHint`'s ERROR with the Ray ID. The library's own NASA queries no longer have those shapes, so a new 403 means Cloudflare blocks one more pattern. Keep probing light: on 2026-11-22 about a dozen requests were blocked over the session without the IP getting blocked, but the WAF's rules aren't published.
  - SIMBAD at CDS accepts no connections on ports 80 and 443. The fallback gives it 5 s and then goes to Harvard, and the cool-down skips CDS after that. So the whole file took 75 s instead of about 12 min, and the SIMBAD tests 1–12 s each instead of about 130 s.
- **Type check**: ty, configured in `[tool.ty]` in `pyproject.toml`: `python-version = "3.12"`, and `allowed-unresolved-imports` with a glob for every third-party module the code imports, plus `setuptools` for `setup.py`. Run it from the repo root in two ways. Plain `ty check` works in the container's system Python only because of those globs, so an import of a new dependency needs a glob there, or that run fails with `unresolved-import`. `ty check --python /tmp/phab-venv` sees the real pandas, NumPy and requests types, and it is the run that finds actual problems. Both must pass. ty neither honours nor flags mypy-coded `# type: ignore[…]` comments, so suppress with `# ty: ignore[<rule>]`, and only where both runs need it: the plain run reports an ignore that only the venv run needs as `unused-ignore-comment`. mypy has been dropped (`mypy.ini` is gone); don't reintroduce it. Full annotations, tests included (`-> None`), are enforced by ruff's `ANN` rules now (see Lint).
- **Lint**: `ruff check`, run from the repo root. Its config is `[tool.ruff]` in `pyproject.toml`:
  - `target-version = "py312"`.
  - `src = [".", "src", "src/phab"]`. The last entry makes the tests' `from utils…` imports first-party, so import sorting (`I001`) keeps them in a group of their own.
  - ruff's own default rule set, deliberately not pinned, plus `ANN` (what mypy's `disallow_untyped_defs` used to enforce), with only `ANN401` ignored: the TAP parameter getters return `Any` on purpose.

  When an image bump brings a ruff with new default rules, fix the new findings instead of ignoring them or pinning the old set. The README's "Linting and type checking" section pins the ruff and ty versions for the user's own runs, in its `uvx ruff@…` and `uvx ty@…` commands. They are the versions the code was last checked with, so when the image's ruff or ty changes and the code passes with it, bump them there too. The code is not ruff-formatted (`ruff format` would rewrite 19 files), so don't run it unless asked.
- **Build a wheel**: `uv build --out-dir <scratchpad>/dist`. `dist/` in the tree is gitignored and holds the user's own builds, so don't build into it. The README's documented route is `python -m build`.
- **License metadata** is the SPDX expression `license_expression = GPL-3.0-or-later` in `setup.cfg`'s `[metadata]` (PEP 639), so there is no `License ::` classifier. Don't add one back: setuptools deprecates them, and next to an expression it refuses to build at all. `license_expression` needs `setuptools>=77` in `[build-system]`, so don't lower that floor. `-or-later` is the user's decision of 2026-11-22, even though the old classifier was the plain `GPLv3` one. Switching to `-only` would change the licensing terms, so ask first. **Read the License metadata section of `.claude/notes/tooling.md` first.**
- **API docs** (pdoc, published at phab.decovar.dev): use the exact README command. It passes `./src/phab/utils ./src/phab/tasks` as paths, sets `PHAB_PACKAGE_VERSION` (shown in the templates) and writes to `documentation/_deploy/`, which is gitignored apart from `.gitkeep`. To check that docs build, use `--output-directory` with a scratch dir. That command is not plain `pdoc` but a `python -c` wrapper: it sets `pdoc.render_helpers.markdown_extensions["toc"]["depth"] = 3` and then calls `pdoc.__main__.cli(sys.argv[1:])`, the function behind the `pdoc` console script, with the same arguments. pdoc hard-codes depth 2, so the sidebar's Contents would otherwise leave out the `###` headings of the `documentation/utils/*/index.md` pages. Don't replace it with plain `pdoc`, and run the wrapper when checking a docs build. Read the Build, docs and live tests section of `.claude/notes/tooling.md` for the evidence.

## Architecture

### One source tree, three import roots

`src/phab/` is a **namespace package** with no `__init__.py`. `setup.cfg` relies on `find_namespace:`, and leaving that out is what broke the 0.8.0 wheels. The subpackages are `phab.utils` (reusable modules), `phab.tasks` (multi-step procedures that combine utils) and `phab.tests`. The same code gets imported under different names depending on the caller:

- **Package users** write `from phab.utils.databases import tap`. All docstring examples use this form.
- **Tests** write `from utils.databases import tap`. pytest puts `src/phab` on `sys.path`, because it is the first directory above the tests with no `__init__.py`. So tests run against the source tree as top-level `utils`/`tests` packages, not against an installed `phab`. Shared fixtures live in `tests/__init__.py` and are imported as `from . import somethingThatDoesntExist  # noqa: F401`. The test parameter that receives one then needs `# noqa: F811`.
- **pdoc** documents the modules as `utils.*` and `tasks.*`. That is why `tasks` modules import with `try: from ..utils… except ImportError: from utils…`. The `except` branch is a deliberate pdoc workaround, so don't remove it. Inside `utils`, always use relative imports (`from ..logs.log import logger`), because only those resolve under all three roots. Cross-references in docstrings use pdoc's names (`` `utils.databases.simbad.getObjectID` ``) so that pdoc can link them.

### Databases layer (`utils/databases/`)

- `tap.py` holds the `services` registry: each endpoint plus flags for that service's quirks, such as `drops-leading-zero-on-cast-to-varchar` and `parameters-that-are-strings`, and optional `mirrors` (a list of URLs, tried in order by `mirrors.tryMirrors`). An `endpoint` is the TAP service's base URL, never `…/sync`: PyVO appends `/sync` itself, which is how the old SIMBAD endpoint ended up requesting `…/sim-tap/sync/sync`. It also holds `mappings` (NASA→PADC column names). `getParameterFromNASA` decides whether a parameter is stellar or planetary by looking it up in the `mappings["NASA-to-PADC"]["stars"]` keys.
- `queryService()` is the single choke point for TAP queries. It sends every query through `_search()`: `mirrors.tryMirrors([tapEndpoint] + getServiceMirrors(tapEndpoint), …)` on `pyvo.dal.TAPService(url, session=mirrors.addConnectTimeout(create_session()))`. A `DALServiceError` is re-raised unchanged, after `getFirewallBlockHint(ex)` is logged at ERROR when it is not empty. On `DALQueryError` it retries once with `escapeSpecialCharactersForAdql()`, which escapes single quotes. It returns `None` for an empty result, so callers test `if results:`. ADQL is built as f-strings with the values interpolated directly, and long queries follow the Long strings convention below.
- The remote databases have quirks, and the workarounds are intentional. Their docstrings explain them and link to the decovar.dev TAP/ADQL blog post, so keep them:
  - NASA rounds doubles in `SELECT` (to the column's `format` in `tap_schema.columns`) but compares the unrounded values in `WHERE`. The workaround is `parameterTypeIsDouble`: `SELECT {param} + 0 AS {param}_real` (an expression has no `format`, so it comes back unrounded) converted with `float()`, and a retry with the range from `_doubleRangeConditionForADQL()` (`0.31212` → `>= 0.3121 AND < 0.3122`, mirrored for negative values). Until 2026-11-22 these were `CAST(… AS REAL)` and a `CAST(… AS VARCHAR(n)) LIKE` retry, which match the same values, but Cloudflare's WAF blocks any `CAST` (see the NASA rule below). Replacing them was the user's decision on 2026-11-22. `strings.conversion.floatToStringForADQLcastVarchar` and the `drops-leading-zero-on-cast-to-varchar` flags stay as public API, but `tap.py` no longer uses them. The `float()` is needed because NASA declares an expression's VOTable type from its values: `int` when every value is a whole number (`st_teff + 0` → `int32`), `double` as soon as one isn't, so no value is truncated.
  - NASA's `TOP` is broken, so queries `ORDER BY pl_pubdate DESC` and take row 0.
  - SIMBAD does not support `CAST`.
  - astroquery 0.4.8 renamed the `query_objectids` column from `ID` to `id`, and the code handles both.
  - `simbad.getObjectID` has a `LIKE` fallback for problematic `main_id`s such as `SZ  66` (two spaces). It has been off by default since 2026.1.9.
- `simbad.py` resolves a star name to SIMBAD's `oid`. It first tries the name as `main_id` in the `basic` table. If that fails, it walks every alias from astroquery's `query_objectids` the same way.
- Mirror fallback (`mirrors.py`) exists because CDS (SIMBAD's main server) has been offline since late October 2026 after a security incident, and since 2026-11-22 it accepts no connections at all. Nothing in the code has to change when CDS is back, because it is tried first again after every cool-down, but the Known problems section of `documentation/utils/databases/index.md` (the published `utils.databases` page), which documents the outage for users, will need updating then. The user decided on 2026-11-22 that this explanation lives there and in docstrings, not in the README. **Before changing the fallback, read `.claude/notes/simbad.md`**, which has the evidence behind these rules:
  - `tryMirrors(servers, attempt)` calls `attempt` with each server in turn. The first one is the main server. It is tried first unless it failed less than `mainServerCooldown` (600 s) ago, according to `_mainServerFailures` (server string → `time.monotonic()`), and a success clears its record. The cool-down is the user's decision on 2026-11-22 and deliberately differs from tap-adql-sandbox, which tries the main server on every call: this library queries in loops (`getObjectID` once per alias, `lookForParametersInGaia` once per star), so 5 s per query would add up. It still recovers by itself once CDS is back, so don't turn it into a permanently cached mirror. The TAP endpoint and astroquery's host name (`simbad.cds.unistra.fr`) are separate keys, so each pays the 5 s once per cool-down.
  - Only `unavailableErrors` (`DALProtocolError`, `OSError`) move on to the next server. PyVO raises `DALServiceError` for HTTP errors and `DALFormatError` for a connection error or timeout in a query, and both subclass `DALProtocolError`. `OSError` covers raw `requests` errors, since `RequestException` subclasses it. `DALQueryError` (a bad query, which SIMBAD returns as HTTP 400 with an ERROR VOTable) is not retried, because every mirror would fail the same way.
  - The last server's error propagates unchanged, and a single-server list is a plain call, with no timeout and no cool-down. Logging: a WARNING for each failed server (the main server's one names the cool-down), an INFO for the mirror that answered after a failure in the same call, and DEBUG for the skip and the answer during the cool-down, so loops don't print two lines per query.
  - The main server gets `mainServerConnectTimeout` (5 s) to accept the connection, but only when mirrors follow it. PyVO and astroquery set no network timeout, so a server that drops connections made each attempt wait out the OS connect timeout (136 s measured). The mirrors get no limit, as in tap-adql-sandbox, where the user decided that on 2026-11-22. It is a connect timeout only, a `(connect, None)` pair. Never add a read timeout: it would cut off a slow query on a working server and send it again to a mirror. Mechanism: `tryMirrors` sets the `_attemptConnectTimeout` ContextVar around the main server's attempt, and `ConnectTimeoutAdapter` applies it to requests that have no timeout of their own. `addConnectTimeout()` mounts that adapter on a fresh `create_session()` per query in `tap._search` and once, at import, on the private `simbad._simbad._session`, which astroquery's `tap` property hands to its `TAPService`. A session without the adapter gets no timeout, so a new query path has to go through `addConnectTimeout()`. requests (2.34.2 here) ships inline annotations, so `ConnectTimeoutAdapter.send` spells out `HTTPAdapter.send`'s full signature: ty rejects a `**kwargs` override as `incompatible-method-override` (and mypy did too). `requests` is in `install_requires` because `mirrors.py` imports it.
  - TAP queries get mirrors only from `getServiceMirrors(tapEndpoint)`, when the endpoint equals a `services` endpoint (trailing `/` ignored). Any other URL, a mirror's included, is never redirected.
  - The SIMBAD ID lookups (`findIdentificatorFromAnotherCatalogue`, `getObjectID`) go through `tryMirrors` on the module's own `_simbad = SimbadClass()`, with `server` set per attempt (`_queryObjectIDs`). Never use astroquery's shared `Simbad` there: the user decided on 2026-11-22 that setting its `server` and mounting the adapter on its session must not leak into the consuming project. The server list (`_getSimbadServers()`) is `conf.server` and then the rest of `conf.servers_list`, from `astroquery.simbad`. The `server` setter rejects any name not in that list, so never hard-code host names there. Released astroquery (0.4.11) lists `simbad.harvard.edu`, not `simbad.cfa.harvard.edu`, and has no IDIA yet.
- NASA Exoplanet Archive queries must get past both Cloudflare's WAF in front of the archive and the archive's own query checks. So they must not contain any of these: `CAST(… AS …)` anywhere (blocked whatever the type and position, `SELECT` included), a string literal followed by `AND`/`OR` and then `<column> IS [NOT] NULL` (put the literal condition last, or write `NOT x IS NULL`), a subquery, `WITH`, `AS` before a table alias (the backend is Oracle and gets the query untranslated, so `FROM ps a`, never `FROM ps AS a`), or more than one condition in `ON`. That is why the NASA functions in `tap.py` put the `hostname`/`pl_name` literal condition last. Only NASA is behind Cloudflare (checked 2026-11-22: PADC, Gaia and both SIMBAD mirrors are not), so the PADC and SIMBAD queries keep their literal-first `WHERE`. Re-run the NASA tests after changing a NASA query. **Before changing them, read `.claude/notes/nasa-exoplanet-archive.md`**, which has the measurements and the rewrites that failed.
- `getFirewallBlockHint(ex)` returns text only for a Cloudflare WAF block page: a `DALServiceError` with `code == 403` whose `ex.cause.response` has `Server: cloudflare` and a `text/html` content type, and the text ends with the `CF-RAY` header. Don't key it on the `Server` header alone, because Cloudflare proxies every response from such a host, a 200 and the service's own VOTable errors included. PyVO keeps the body only for `text/plain` errors, so without the hint the user sees a bare `403 Client Error: Forbidden`.
- `lightcurves.py` wraps lightkurve searches. The `authors` dict maps each author to its mission and cadence values, and `lightCurveFluxTableSchema` (pandera) validates the flux tables it produces.
- `fitsToPandas` relies on `numpy.array(table)` of an astropy `Table` being in native byte order. `Table.as_array()` guarantees that since astropy 1.1, which is older than any astropy installable on Python 3.12 (5.3.4), so `install_requires` doesn't pin it (the user's decision, 2026-11-22). The FITS columns of the `Table` itself stay big-endian, but the array no longer is. So don't add a byte swap back: it would turn the columns big-endian, as the one removed on 2026-11-22 did. With pandas ≤ 3.0 the DataFrame turned them native again, but since 3.1.0 they stay big-endian. Platform doesn't matter here, because every supported platform is little-endian. **Before touching the byte order there, read the Byte order section of `.claude/notes/tooling.md`.**

### Cross-cutting conventions

- **Logging**: modules log through `from ..logs.log import logger`. That is a `phab` logger writing to stdout with `propagate = False`, so it doesn't change logging in the consuming project. The `PHAB_DEBUG` env var switches it to DEBUG with timestamps; any value except `0`/`no`/`off`/`false`/`disable` turns it on. It is read once, at import time, in `utils/logs/__init__.py`.
- **Docs are the docstrings**: every public function's docstring has an `Example:` with a ```` ``` py ```` block. Each subpackage's `__init__.py` docstring is `.. include:: ../../../../documentation/utils/<name>/index.md`, so a new subpackage needs a matching `documentation/utils/<name>/index.md`.
- **Naming**: functions, variables and parameters are camelCase (`getObjectID`, `parameterTypeIsDouble`). Module names and test functions are snake_case.
- **Shadowing module name**: `utils/datasets/pandas.py` has the same name as the real `pandas`, and its own docstring requires an alias. Always import it as `from ..datasets import pandas as pnd`, and keep `import pandas` for the library.
- **Python version**: 3.12 is the minimum, so 3.12 syntax is fine: PEP 695 type parameters (`mirrors.tryMirrors[T]`), PEP 701 f-strings, parenthesized context managers. ruff's `UP` rules enforce `X | None`, builtin generics (`list[str]`) and `collections.abc` imports over their `typing` forms. The minimum is declared in four places that change together: `python_requires` and the classifier in `setup.cfg`, `target-version` under `[tool.ruff]` and `python-version` under `[tool.ty.environment]` in `pyproject.toml`. The last two have to be explicit, because both tools infer the version only from `[project].requires-python`, and this project has no `[project]` table. The README names no Python version. Ask before raising it further.
- **Dependencies**: every third-party module that library code (`utils/`, `tasks/`) imports belongs in `install_requires`, even when another dependency brings it in anyway (as with `requests` for `mirrors.py`). Test-only imports don't. That is why `packaging` is not listed: only `tests/databases.py` imports it, and pytest depends on it. If library code imports `packaging` again, as `lightcurves.py` did for a NumPy version check until 2026-11-22, add it to `install_requires`. Any new third-party import also needs its glob in ty's `allowed-unresolved-imports` (see Type check).
- **Long strings**: adjacent string literals inside parentheses (implicit concatenation), one fragment per line, each ending with the space that separates it from the next.
  - Plain and f-string fragments mix freely, and a computed part goes into an f-string field (`f"in this table: {', '.join(ids.colnames)}"`).
  - A string that is a call's only argument needs no extra parentheses (ruff `UP034`). It needs its own when it is one of several arguments, like the ADQL passed to `queryService()`, or an element of a list or tuple (`ISC004`).
  - A conditional fragment can't be part of an implicit concatenation, so it goes into a local variable right above the query, together with its comments (`selectClause` and `valueCondition` in `tap.py`).
  - `str.join` is only for runtime sequences. The fixed-tuple `" ".join((…))` idiom has been replaced everywhere in the code (ruff `FLY002` flags most of it), though docstring examples and commented-out code still contain it.

## Releases

- Versioning has been date-based since 2026.1.9. `__version_info__ = (YYYY, M, D)` (no zero padding) lives in `src/phab/utils/_version.py`, and `setup.cfg` reads it via `attr:`. PyPI won't accept the same version twice.
- Each release adds a section at the top of `changelog.md`. It starts with `` Released on `YYYY-MM-DD`. `` and nests bullets as module → submodule → function. Add the new heading to the `MarkdownTOC` block as well.
